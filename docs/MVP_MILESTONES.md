# Chrome AI 标签整理器 - MVP 里程碑（MiniMax-only）

## 1. 里程碑总览
- P0：主流程闭环可用（MiniMax-only）。
- P1：稳定性与可用性强化。
- P2：性能与扩展预留优化（不引入新 provider）。

## 2. P0 - 主流程可用（必须完成）
目标：用户可在 Chrome 内完成 `分析 -> 预览 -> 执行 -> 撤销最近一次`，并可在设置页手动查看 Token Plan 额度。

交付项：
- MV3 骨架（background + popup）。
- MiniMax Chat Completions 接入（默认 `MiniMax-M2.7`）。
- 范围切换、纳入已有分组开关、混合/域名优先模式。
- 预览编辑（组名/颜色/成员归属）。
- 执行分组与最近一次撤销。
- 设置页 MiniMax Key/Model + Token Plan remains 手动刷新。
- 中英双语基础文案。
- 旧 provider 配置自动归档忽略。

完成定义（DoD）：
- 在 30-80 标签样本下主流程稳定可用；
- AI 失败路径零变更；
- 额度查询成功与失败提示清晰；
- 旧配置不阻塞升级。

## 3. P1 - 稳定性与体验（应该完成）
交付项：
- `401/403/429` 错误映射与提示统一；
- telemetry 指标面板（可关闭）；
- 提案完整性校验增强（重复 tabId、非法颜色、孤儿标签）；
- remains 缓存与刷新体验优化。

完成定义（DoD）：
- 80 标签分析 <= 10 秒（正常网络）；
- 连续多轮执行/撤销后状态正确；
- 无 provider 分支残留逻辑导致的回归。

## 4. P2 - 优化与预留（可以完成）
交付项：
- 主流程性能优化（批量操作顺序与异常分支）。
- 文档补全（排障手册、回归清单）。
- 后续扩展设计文档（树形视图、自动触发）仅文档，不实现。

完成定义（DoD）：
- 优化项不引入稳定性回归；
- 运维排障路径清晰；
- 后续扩展具备可执行的接口边界说明。

## 5. 推荐执行顺序
1. 先打通 MiniMax-only 分析链路与主流程闭环。
2. 接入 remains 查询与缓存。
3. 完成配置迁移与错误映射。
4. 做性能与交互回归。

## 6. 发布退出条件
- P0 与 P1 DoD 全部通过。
- PRD 验收条款通过。
- 在干净 Chrome 配置中完成权限、隐私、失败行为验证。
